# Решения и вопросы по MVP

_Обновлено: 2026-09-22._

## Принятые решения

| Область              | Решение                                                                                                                                                                                                                  |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Цель                 | Реализовать весь MVP, заданный исходной постановкой.                                                                                                                                                                     |
| Развёртывание        | На текущем этапе только локальная разработка; cloud/production hosting не входит в scope.                                                                                                                                |
| Безопасность         | Нужна практичная защита без Redis, внешних очередей, RS256 и другой преждевременной инфраструктуры.                                                                                                                      |
| Владелец кампании    | Мастер — это `Campaign.owner`; роль `MASTER` в `CampaignMember` не нужна.                                                                                                                                                |
| Изоляция данных      | Кампания — tenant. Доступ к данным всегда ограничен конкретной кампанией и её membership.                                                                                                                                |
| Участники            | Поддерживаются прямое добавление зарегистрированного пользователя и invitation link.                                                                                                                                     |
| Игровые системы      | Нужна расширяемая модель, но в MVP достаточно одного шаблона Tales from the Loop.                                                                                                                                        |
| Персонажи игроков    | У игрока один активный персонаж в кампании; владелец создаёт неограниченные NPC. Membership достаточно для доступа к разрешённому контенту.                                                                              |
| Invitation link      | Одноразовая, действует 7 дней, содержит роль; владелец может отозвать. Повторное принятие действующим участником возвращает `409 Conflict`.                                                                              |
| Visibility           | `PRIVATE` — только автор; `MASTER_ONLY` — владелец; `PLAYERS` — владелец и игроки; `PUBLIC` — все участники. Public ограничен кампанией.                                                                                 |
| Чужие tenant-ресурсы | Возвращать `404 Not Found`, не раскрывая факт существования кампании или её данных.                                                                                                                                      |
| Стол расследования   | Один на кампанию; универсальные карточки без типов, свободные теги, цвет и иконка. Владелец и игроки совместно изменяют любые карточки и ненаправленные связи. `VIEWER` не имеет доступа; загрузка изображений не нужна. |
| Фронтенд             | Локальный React-клиент — следующий продуктовый этап после backend-этапа 3; технический каркас можно начать после этапа 2.                                                                                                |
| Корневые документы   | В корне сохраняется только общий `README.md`; рабочие артефакты находятся в `resources/`.                                                                                                                                |

## Открытые решения

### Файлы раздаток в локальном MVP

Нужно выбрать первый способ хранения:

- только внешняя ссылка `fileUrl`;
- локальная загрузка в каталог приложения;
- оба варианта.

**Текущее предложение:** начать с валидируемого `fileUrl`, как в исходном плане. Локальную загрузку добавить отдельным улучшением после завершения CRUD и авторизации.

### Детали стола расследования

Приняты: один стол на кампанию; универсальные карточки без типов; свободные теги; цвет и иконка; ненаправленные связи с необязательной подписью; сохранение координат для будущего интерфейса. Владелец и все игроки совместно управляют любыми карточками и связями. Загрузка изображений не требуется.

До реализации фронтенда нужно выбрать только визуальный набор иконок и формат палитры цветов. Эти детали не влияют на backend-модель.
